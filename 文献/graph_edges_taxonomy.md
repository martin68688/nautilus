# 图记忆论文的"边多样性"横向盘点

> **核心问题**：你的双曲 Skill 图有 7 类边（含 `prevents` 冲突边）。这个"边多样性"是否真的是优势？要回答这个问题，必须把所有图记忆论文的边做**穷尽式结构化盘点**，看它们的边到底多不多样，是否存在语义空白。
>
> **结论先行**：现有图记忆论文的边**普遍不多样**——绝大多数停留在"相似/包含/时序"三类**中性关系**，几乎不存在"冲突/对立"这类**对抗性关系**。你的 `prevents` 冲突边落在了一个**真实的、跨所有论文的空白象限**。但"边多"不等于"边有用"——本文也指出了你必须警惕的陷阱。

---

## 1. 逐论文边类型详盘

### 1.1 A-MEM（arXiv:2502.12110，NeurIPS'25 poster）
- **边类型**：仅 `similar_to`（1 类）
- **语义**：纯语义相似链接（Zettelkasten 风格的笔记互连）
- **建边方式**：LLM 在记忆构造阶段自主生成 note 时决定与哪些旧 note 建链
- **评价**：**最弱的边**。边只编码"这俩有点像"，无层级、无因果、无冲突。A-MEM 的 §2.2 自白"agency 在存储与演化，检索让给 agentic RAG"——它的边信息量低到检索时干脆不用边，直接退回纯向量。

### 1.2 Mem0ᵍ（图版，arXiv:2504.19413）
- **边类型**：3 类隐式分类——`explicit`（显式关系）/ `implicit`（隐式关系）/ `temporal`（时序关系）
- **语义**：实体间三元组 `(v_s, r, v_d)`，r 是自由文本关系标签（如"住在"、"就职于"）
- **建边方式**：Entity Extractor 抽实体 + Relationship Generator 判关系
- **评价**：**关系标签自由但语义浅**。r 可以是任何自然语言，但系统不区分 r 的语义类别（不区分"因果"和"巧合"）。且实测：图版比基础版只高 2%，延迟翻 3 倍——**边的多样性没换来收益**。

### 1.3 Zep / Graphiti（arXiv:2501.13956）
- **边类型**：1 类，但带**双时序戳** `valid_at` / `invalid_at`
- **语义**：实体/事件间的关系，核心是"何时有效"
- **建边方式**：后端 pipeline 自动抽取/去重/失效
- **评价**：**时序维度做得最深**，但只有时序。`invalid_at` 能判"谁更新"（动态冲突），但判不了"两个同时有效但矛盾"（双真冲突）。是**最客观但最单一**的边。

### 1.4 EXG（arXiv:2605.17721）
- **边类型**：3 类——`contain`（anchor→case，归属）/ `similar`（无向带权，语义相似）/ `fixed_by`（case→case，纠错）
- **语义**：包含 + 相似 + **纠错（已有因果意味）**
- **建边方式**：固定规则（相似边由加权公式 `s=α⟨e_p,e_p⟩+(1-α)h·h⟨e_f,e_f⟩` 自动算，α=0.8）
- **评价**：`fixed_by` 是**第一个有因果意味的边**（"这次修复了上次的错"），但仅限"错误→修复"单一因果。无冲突、无条件、无细化。检索时路径永远 ≤2 跳（similar 1 步 + fix 1 步），**边种类少导致检索深度受限**。

### 1.5 SAGE（arXiv:2605.12061）
- **边类型**：N 类（自由 typed directed 关系）+ alias（别名）+ 时序约束
- **语义**：理论上任意（因为是训练式 writer 学出来的）
- **建边方式**：GRPO 训练的 writer 策略网络输出"实体-关系三元组 + source anchor"
- **评价**：**理论上最自由**（可学任意关系），但**实际语义不可控**——writer 学出的关系是黑箱，不保证有解释性。冲突靠独立的 LLM Conflict Detector（不是边），时序靠失效标记。**边自由度高但牺牲了可解释性**。

### 1.6 SkillGraph（arXiv:2605.12039）⭐ 最近竞品
- **边类型**：3 类——`prereq`（前置）/ `enhance`（增强）/ `co_occur`（共现）
- **语义**：依赖（前置序）+ 协同（增强）+ 统计（共现）
- **建边方式**：RL 反馈演化（Path reinforcement 强化成功路径、Co-occurrence discovery 发现新共现、Decay-pruning 衰减剪枝）
- **评价**：**三类都是正向/协同关系**。`prereq` 是依赖序（强），`enhance`/`co_occur` 是弱协同。**完全没有冲突、没有条件、没有失败**。边权重可演化（动态），但语义类别固定 3 种。

### 1.7 GoS / Graph-of-Skills（OpenReview HfGDY8mV67）
- **边类型**：4 类——`dep`（依赖）/ `wf`（工作流）/ `sem`（语义）/ `alt`（替代）
- **语义**：依赖 + 流程序 + 近义 + 可互换
- **建边方式**：`dep` 确定性 I/O schema 匹配（无 LLM）；其余 3 类稀疏 LLM 验证 O(N·k)
- **评价**：**边类型最多样的"工程派"**。`dep`（确定性）+ `alt`（替代）是独特组合。但仍**无冲突、无条件、无失败**，且图静态不演化。`alt`（替代）接近"对立"但不是——替代是"可互换"，不是"互斥"。

### 1.8 GAM（arXiv:2604.12285）
- **边类型**：2 类——`topic`（主题网络内边，LLM 算权重）/ `cross`（跨层索引，topic→event graph）
- **语义**：主题关联 + 层级索引
- **建边方式**：topic 边权靠 LLM scorer（贵）；cross 边是结构索引
- **评价**：**边最少样**（实质就主题关联 + 跨层指针）。GAM 的卖点在 consolidation 机制（防 contamination），不在边多样性。

### 1.9 InternAgent-1.5 SKM（arXiv:2602.08990）
- **边类型**：3 类——`cites`（引用）/ `by_product`（副产品）/ `prerequisite`（前置）
- **语义**：学术引用 + 因果副产品 + 依赖
- **建边方式**：人工/半自动
- **评价**：科研场景的边（cites/by_product 有领域特色），`prerequisite` 与 SkillGraph 撞型。无冲突、无条件。

## 2. 边语义的六维分类（核心洞察）

把所有论文的边按**语义类别**归到 6 个维度，能清晰看到空白：

| 语义维度 | 含义 | 谁有？ | 信息量 |
|---|---|---|---|
| **① 相似/关联** | "这俩像" | A-MEM, Mem0ᵍ, EXG, GoS(sem), GAM | 🟡 弱（向量也能做） |
| **② 包含/归属** | "A 属于 B" | EXG(contain), Mem0ᵍ | 🟡 中（层级） |
| **③ 依赖/前置** | "A 先于 B" | SkillGraph(prereq), GoS(dep), InternAgent(prereq) | 🟢 强（序） |
| **④ 协同/共现** | "A+B 一起好" | SkillGraph(enhance,co_occur), GoS(wf) | 🟡 中（统计） |
| **⑤ 时序/演化** | "A 后来被 B 更新" | Zep(valid_at), SAGE(时序), SkillGraph(演化) | 🟢 强（客观） |
| **⑥ 替代/可换** | "A 或 B 都行" | GoS(alt) | 🟡 中 |
| **⑦ 条件/适用** | "A 在条件 C 下有效" | **无（仅你的 applies_when）** | 🔴 **空白** |
| **⑧ 冲突/对立** | "A 和 B 互斥" | **无（仅你的 prevents）** | 🔴 **空白** |
| **⑨ 失败/规避** | "A 防止失败 F" | **无（仅你的 prevents→FailureMode）** | 🔴 **空白** |

### 关键发现：三个语义空白象限

**所有图记忆论文的边，都集中在①②③④⑤⑥这六个"中性/正向"维度**。下面三个维度是**跨所有论文的空白**：

1. **⑦ 条件（applies_when）**：没有任何一篇用边表达"这个 skill 在什么条件下适用"。SkillGraph 的 condition 是**节点内的字段**（不是边），其他论文根本没有条件概念。
2. **⑧ 冲突（prevents）**：没有任何一篇用边表达"这两个互斥"。Zep 的时序失效是"谁更新"（动态冲突），不是"同时有效但对立"（双真冲突）。
3. **⑨ 失败规避（prevents→FailureMode）**：没有任何一篇把"失败模式"作为可连接的节点。EXG 的 `fixed_by` 是"错误→修复"，但失败本身不是独立节点。

> **这是你最强的文献空白论据**：你的 7 类边里，有 **3 类（applies_when/prevents/prevents→FailureMode）落在跨所有论文的空白象限**。这不是"边多"，是"边覆盖了别人没覆盖的语义"。

## 3. "边多"≠"边有用"：你必须警惕的陷阱

诚实地说，"边类型多"本身**不是 novelty**，审稿人会质疑。以下是三个陷阱：

### 陷阱 1：边冗余（可能被合并）
你的 7 类边里，`refines`（细化）和 `prerequisite`（前置）在几何上**几乎相同**（都是 Δr>0, Δθ≈0）。区别只是"带不带序"。审稿人会问："这两个能合并吗？"
- **你的应答**：保留区分，但论文里要证明**去掉任一类检索质量下降**（消融）。

### 陷阱 2：边无用（建了不检索）
如果建了 `co_occurs` 边但检索时从不走它，那它就是死边。
- **你的应答**：论文里必须报告**每类边的检索命中率**（usage stat），证明 7 类边都被实际用到。

### 陷阱 3：边的主观性（metric 没法监督的边）
`metric_delta` 能监督半径（层级），但**监督不了角度**。`applies_when`/`prevents` 这类边的角度位置靠 LLM 判断条件语义——这又回到了"LLM 主观判定"的老问题。
- **你的应答**：用 metric **反向校准**——如果两个被标 `prevents` 的 skill 实际 metric 都提升，说明标错了，降权。这是把客观信号延伸到边判定。

## 4. 对你研究的启示

### 启示 1：novelty 不在"7 类"，在"3 个空白象限"
不要把卖点写成"我们边最多"（会被打）。要写成：**"我们的边覆盖了现有所有图记忆都缺失的三个语义维度——条件、冲突、失败规避"**。这是基于空白的 novelty，不是基于数量的 novelty。

### 启示 2：SkillGraph 是"边少但深"的代表
SkillGraph 只有 3 类边，但每类都**演化 + 阈值化 + 可消融验证**。你的 7 类边如果只是"定义了"但没验证每类的边际贡献，反而不如它。**必做**：7 类边的逐类消融（去掉每类看指标掉多少）。

### 启示 3：GoS 的 `alt`（替代）是你 `prevents`（冲突）的"弱化版"
GoS 的 `alt` 是"可互换"（A 或 B 都行）——这是**协同**。你的 `prevents` 是"互斥"（A 和 B 不能同时用）——这是**对抗**。两者几何上接近（同层不同向），但语义相反。论文里要**明确区分 alt vs prevents**，否则审稿人会问"你这不就是 GoS 的替代吗？"

### 启示 4：条件边（applies_when）是被严重低估的空白
`applies_when` 是所有论文都缺的。它解决的是"低频 skill 在什么条件下才该被召回"——这直接服务你的主贡献1（反 prevalent bias）。**建议强化这类的叙事**：双曲角向位置编码条件，让"小数据集条件下的 skill"聚在特定扇区，检索时按当前任务的条件扇区定位。

**一句话总纲**：
> **现有图记忆的边集中在"相似/包含/依赖/协同/时序"五个中性维度，条件/冲突/失败规避三个语义维度是跨所有论文的空白。你的 7 类边里这 3 类恰好独占——novelty 不在"边多"，在"边覆盖了没人覆盖的语义"。但必须用逐类消融证明每类边都被实际检索用到，否则"边多"会变成被攻击的靶子。**

## 6. 论文 Related Work 可用段落

> "现有图结构 agent 记忆的边类型普遍限于中性关系：A-MEM 仅用 `similar_to` 表达语义相似；EXG 扩展至 `contain`/`similar`/`fixed_by` 但仍无对抗性关系；SkillGraph 的 `prereq`/`enhance`/`co_occur` 全部为正向协同；GoS 的四类边（`dep`/`wf`/`sem`/`alt`）最多样，但其 `alt` 表达的是可互换性而非互斥性。**据我们所知，没有任何图记忆系统用显式边表达"条件适用性"、"双真冲突"或"失败规避"这三个语义维度。** 本研究填补此空白，以 `applies_when` 编码条件适用、`prevents` 编码双真冲突、`prevents→FailureMode` 编码失败规避，且三者均由 metric_delta 与几何位置客观派生，而非 LLM 主观判定。"
