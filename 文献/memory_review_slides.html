动机：瓶颈不是单步推理，是记忆

agent 从"单次执行器"升级为"持续学习者"卡在哪

真实部署的 agent 是长周期、多任务的

  • 它需要记住：上次怎么失败的、哪个方法有效、哪些条件变了
  • 单步推理已足够强 —— 缺的是跨任务 / 跨会话 / 跨失败的经验积累、组织与复用
  • 2025–2026 涌现大量记忆工作，但高度碎片化，无一通吃

记忆问题的本质（MemConflict）

Memory validity is a "query-conditioned fitness-for-use" problem.
记忆有效性 = "在当前查询下能否提供正确、有效、适用的信息"

这把记忆从存储问题抬成推理问题 —— 不是"存了就行"，而是"找到矛盾时该信谁"。

与普通 RAG 的边界： RAG 解决"找得到"；本研究关心的是 "找到了若干相关甚至矛盾的经验，怎么组织、怎么判定、怎么多跳追溯"。

为什么 MLE 场景是天选切入点

MLE 经验记忆 vs 对话记忆的四个本质差异 —— 每个都逼出新机制

差异对话场景MLE 场景（mlevolve）逼出的机制
因果关系语义相似（similar_to 够用）执行派生（B 改进 A，metric 变化）异构因果边
可验证性无法验证对错code 可重跑、metric 是 ground truth客观质量信号
冲突性质一真一假双真（两次执行都真实但矛盾）基于条件的判定
内容类型文本事实可执行代码 + metricverifiable code memory
不可替代的核心： 对话的 static 冲突是"真值 vs 错误"，LLM 多少能靠语义猜； MLE 的 static 冲突是"两次真实执行结果矛盾" —— LLM 没有先验知道信谁， 只有 metric 和执行条件能判定。
现成资产： Spooky 任务 60+ 个 run、手工 15 条 ground-truth insight， 双真冲突案例已经在硬盘上，离线验证不依赖新算力。

Approach · 3-layer pipeline7 / 13

双层记忆协调：Layer A + Layer B 绝不合并

两层回答根本不同的问题，不能互相替代

Layer A · Trace 记忆（保留现状）

GlobalMemoryLayer + SearchNode 树
回答"这个分支已经试过什么？结果如何？"
语气描述性（事实陈述）
时间尺度当前 run（小时级）
粒度具体 code + 具体 metric
呈现强制注入 prompt（agent 必看）

Layer B · Skill Graph（新增）

蒸馏产物的图 + agent 多跳 tool
回答"这种情况下方法学告诉我该怎么做？"
语气规范性（方法建议）
时间尺度跨 run（周/月级）
粒度抽象 SOP + 适用条件
呈现按需 tool 查（agent 自主决定）
互补性证明： 只信 Layer B → agent 不知道"刚才这个分支试 DeBERTa-large 已失败"，重复犯错； 只信 Layer A → agent 只看到当前分支 5–10 次尝试，永远局部探索。 当前 run 内 Layer B 只读不写，保证图稳定、不被单次实验污染。

图存在的理由：发现"语义外"联系

同一个 improve 场景 · 向量检索 vs 图多跳 —— 这是图不可替代的硬核场景

向量检索 返回"同一类思路的变体"
Query "reduce overfitting on small NLP dataset"
Top-3 use stronger dropout
Top-3 use weight decay
Top-3 use early stopping
三条都和 query 语义近，但互相之间也近 —— agent 拿到的是同一思路的不同变体，信息冗余。
图多跳 沿 PREVENTS 追同一 failure mode
Start 当前 SOP = "partial unfreezing"
Walk SOP →PREVENTS→ FailureMode "small-data overfitting"
Walk ←PREVENTS← 其他 SOP
Hit label smoothing  (文本不近)
Hit longer epochs + warmup  (文本不近)
Hit stratified k-fold CV  (文本不近)
三个 SOP 解决同一 failure mode 但是不同路径 —— agent 看懂"是组合用，不是替代"。
冲突处理同理： SOP_A "用 label smoothing" vs SOP_B "别用" —— 沿各自 PREVENTS 发现 解决的是不同问题 → 不是真冲突，是适用条件不同 → 加 refines 边（条件分支保留）， 不是覆盖。
Vector vs graph multi-hop10 / 13

实验设计：不赌端到端，先证机制

专项实验比"比最终 metric"更直接、更有说服力

主实验

  • 3 条件对照：No-Mem / 平面+固定向量（现状）/ Skill Graph + agent 多跳
  • 指标：最终 metric、收敛速度、重复错误率
  • 约 12 GPU·h，先在 Spooky 出信号

★ 专项实验差异化

  • Path Diversity@K：图检索 SOP 的文本方差是否更大
  • Hidden Link Recall：能否召回向量找不到的"语义远但相关"SOP
  • 冲突分类正确率：图证据是否把 LLM 判定从 ~60% 提到 ~80%

消融

  • w/o 因果边
  • w/o 多跳（退化成一跳）
  • w/o agent 自主（固定注入）
  • w/o metric 判定
P1 验证锚点（离线、不烧算力）： 自动蒸馏产 ≥30 patch， 对比手工 15 条 ground-truth insight，召回 ≥10/15、新发现 1–2 条、条件标注 100%。
投稿目标：对标 A-MEM（NeurIPS'25 poster）→ NeurIPS / ICML / ICLR poster；每层贡献可独立验证，避免"全有或全无"。

风险 + "什么会让我放弃"

主动暴露弱点 —— 这是我最想听你意见的地方

风险 1 · novelty 被质疑增量

"图 + agent 检索"会被说成 EXG/A-MEM 的拼接。
对策：用消融证明组合效应 > 各部分之和；锚定"节点是 procedural"这条文献空白。

风险 2 · agent 检索延迟

每跳 +1 LLM call，单次更贵。
对策：报告 p50/p95 延迟与 token 成本，论证"减少试错步数、端到端更快"。

风险 3 · 条件抽取质量

applies_when / failure mode 依赖 LLM 归因，可能噪声大。
对策：用 metric_delta 反向校准；多人标注 ground truth。

Kill criteria： 如果专项实验里图多跳的 Hidden Link Recall 不显著高于向量检索， 核心 claim 就不成立 —— 我会回去检查节点/边 schema，而不是硬写论文。
