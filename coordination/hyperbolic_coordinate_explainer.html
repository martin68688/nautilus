双曲 SOP 记忆坐标到底在表达什么

这张图解把当前 v0 产物拆成三件事：SOP 点被放进 Poincare 球，Poincare 点可转换成 Lorentz 双曲面点，runtime 现在还没有用这些坐标做检索。

先抓住一个比喻

普通向量检索像把所有方法卡片摊在一张平桌上。双曲结构像把它们放进一座向外扩张很快的城市：中心放通用方法，外圈容纳大量细条件分支。

当前 v0 已经把卡片放到了这座城市的坐标里，但检索员还没有按城市里的距离开车。

关键词：坐标已生成；坐标还没主导检索；Flat-Twin 还不是独立地图。

1. Poincare 球：像一张压缩进圆里的地图

core: 更中心 middle: 中层 edge: 外圈

Poincare 球的边界永远到不了。越靠边，双曲距离膨胀越快，所以外圈能容纳很多细分方法。

坐标字段逐个翻译成人话

direction = 方向。 当前由 `title + principle + condition + category + scope` 做 TF-IDF-SVD 得到。它像指南针，决定这个 SOP 放在哪个扇区。

theta = 平面方位角。 在 x-y 投影里，绕中心转了多少度。相近 theta 的 SOP 大致在同一方向。

phi = 上下倾角。 因为实际是 H3 / 3D 球，不只是圆盘。phi 表示它偏向 z 轴上方还是下方。

radius = 离中心多远。 当前由 `p_hat / n_use / level` 近似。越可靠、越常用、越通用，越应该靠中心；越窄、越低支持，越靠外。

poincare = 球内坐标。 真实形式是 `(x,y,z)`，满足 `||p|| < 1`。当前最大 norm 约 0.867，合法在球内。

poincare = direction * radius

注意：这里的 direction 质量还弱，半径也是 proxy。所以它是一张 v0 草图，不是最终学出来的城市地图。

2. Lorentz 双曲面：同一个点的另一种坐标写法

Poincare 球适合可视化；Lorentz 双曲面适合稳定计算距离。两者可以互相转换。

Lorentz 公式的直觉

Poincare 点 `p=(x,y,z)` 在球里。Lorentz 把它抬到一个四维点：

t = (1 + ||p||^2) / (1 - ||p||^2) space = 2p / (1 - ||p||^2)

这个点满足：

t^2 - ||space||^2 = 1

直觉是：Poincare 越靠边，分母 `1-r^2` 越小，Lorentz 的 `t` 会迅速变大。也就是外圈在双曲空间里其实离中心很远。

当前 builder 的 Lorentz 约束最大误差约 1.14e-5，所以数学转换本身是成立的。

3. 真正的双曲检索应该怎么用这些坐标

任务上下文 比如 small data、overfitting、CUDA OOM、Transformer fine-tuning。
→
投到地图上 把 query 也变成一个 Poincare 或 Lorentz 点。
→
按双曲距离找 SOP 近的先看，再结合 condition、evidence、conflict 过滤。

这才是“坐标成为检索决策核心”的含义：不是只展示坐标，而是让距离参与排序。

应该发生的事

  • 加载 `hyper_index.npz`。
  • 建立 `sop_id -> poincare/lorentz`。
  • query 也映射成地图点。
  • 用 Poincare 或 Lorentz distance 排序。

现在发生的事

  • runtime 没加载坐标索引。
  • 没有 Poincare/Lorentz 距离计算。
  • `navigate` 主要用 token 匹配和规则 bonus。
  • prompt 名字里有 hyperbolic，但检索器还没看坐标。

4. Flat-Twin 为什么现在不成立

Flat-Twin 应该是证明“双曲本身有效”的对照组。但现在：

flat_twin = directions * radii[:, None] poincare = directions * radii[:, None]

所以它目前只是同一份坐标的另一个 key。未来可以用同一点位但不同距离度量做初步对照，也可以重建真正 Euclidean-only 坐标。

5. 为什么 p_hat=0 的外圈要小心解释

设计理想里，外圈应该装很多“条件窄但有用”的 SOP。当前 v0 里，外圈还混入了“没有成功证据”的 SOP。

外圈现在更准确的含义：低支持、低成功率、深层级、细条件节点的混合区。不能直接等同于“稀有宝藏”。

一句话收束

当前双曲结构像一张已经画好经纬度的城市地图：Poincare 是城市平面投影，Lorentz 是更适合算距离的数学坐标，radius/theta/phi 描述每个 SOP 在地图上的位置。

但当前 runtime 还没有真正按这些坐标导航。它仍主要按文字相似度找 SOP，所以现在应该叫“带双曲坐标的 v0 SOP 图 + agentic navigator 外壳”，不能叫“已经完成的双曲检索系统”。
