🌳 同一棵树，三种几何 · 双曲 vs 平面 vs 球面

用完全相同的坐标 (r,θ)，在三种几何下画同一棵 4 层 skill 树。看哪种能"装得下"且不失真。

我们先定义同一棵树（4层，每个节点分3叉），然后看它在三种几何下的命运：

这棵 skill 树（你的 skill 层级）：

L0(根): 优化方法 → L1: 梯度下降 / 树模型 / 神经网 → L2: Adam/SGD, XGB/LGBM, CNN/Transformer → L3: Adam的lr, XGB的max_depth, ... (27 个叶子节点)

① 同一棵树，放在三种几何里

平面 ℝ²（曲率=0）
距离 = √(Δx²+Δy²)，面积 = πr²
❌ 装得下但严重失真

面积 = πr² 线性增长。第3层的27个节点挤在边缘一小块区域，彼此距离太近，区分不开。层级越深越挤。

球面 S²（曲率>0）
面积 = 4πR² 有限！
⚠️ 比 L2 还拥挤，且会"撞南墙"

球面总面积有限。树越深，叶子越多，但球面"赤道外"空间反而收窄（像地球两极挤一起）。装不下无限深的树。

双曲 ℍ²（曲率<0）
面积 = 2π(cosh(r)−1) 指数增长！
均匀分散，互不重叠
✅ 完美展开，无失真，可无限深

面积 = 2π(cosh(r)−1) 指数增长。第3层的27个节点在边缘有充足空间均匀分散。层级越深，边缘空间越多，永远不会挤。

🎯 看明白了吗？ 三个图用的是完全相同的树结构（同样的4层、同样的分叉）。 - 平面：第3层27个叶子挤成一团，区分不开（面积线性增长，边缘不够用） - 球面：总面积有限，越深越挤，还会"撞墙"（球面无法装无限树） - 双曲：第3层27个叶子均匀分散，每个都有自己的位置（面积指数膨胀）
这就是"为什么只有双曲能装下树"的视觉证明。

② 数学根源：三种几何的"面积增长速度"

同样半径 r 处的可用面积（决定能装多少节点）：

几何半径r处的圆周长增长速度直观
平面 ℝ²2πr线性越往外，空间匀速增加 → 深层节点挤
球面 S²2π·sin(r)先增后减，有限赤道最大，两极收窄到0 → 撞墙
双曲 ℍ²2π·sinh(r)指数！越往外空间爆炸式增加 → 无限装
关键：sinh(r) 是指数函数。 当 r=3 时，平面周长≈6π，双曲周长≈200。 同样的"半径3"，双曲能装的节点数是平面的30倍。 这就是为什么深层 skill（具体 patch）在双曲里有充足空间，在平面里挤成一团。

③ B部分：2D 双曲 ℍ² vs 3D 双曲 ℍ³ 该选哪个？

2D 双曲 ℍ²（Poincaré圆盘）

坐标：(r, θ) — 半径 + 1个角度

能表达：

  • ✅ 层级深度（r）
  • ✅ 一个语义轴（θ）

适合：skill 数量 < 500，语义类别单一（如纯 MLE 方法）

优点：简单、稳定、可视化（圆盘图）

缺点：只能表达一个正交语义轴

3D 双曲 ℍ³（Poincaré球）

坐标：(r, θ, φ) — 半径 + 2个角度

能表达：

  • ✅ 层级深度（r）
  • ✅ 两个正交语义轴（θ, φ）

适合：skill 数量 > 500，需要区分多种正交语义（领域×类型）

优点：能表达两个正交语义轴

缺点：计算贵，无法直接2D可视化

推荐维度数（基于你的 skill 数量）

你的 skill 规模推荐几何理由
< 100 个ℍ² (2D)够用，简单
100–500 个ℍ² (2D)仍够用，一个语义轴足够
500–2000 个ℍ³ (3D) 或 ℍ⁵需要多个正交语义轴来区分
> 2000 个ℍ⁵ (5D)多语义轴避免不同类 skill 重叠

⚠️ 注意：维度不是越多越好。双曲的高维会指数级增加计算成本，且数值不稳定。你的 skill 库如果只有几百个，2D 完全够用。盲目上高维是过度工程。

④ C部分：ℍ³ / ℍ⁵ 的具体坐标轴怎么定义？

如果你要从 2D 升级到多维双曲，每个正交轴该放什么？核心原则：每个角度轴放一个"正交的语义类别"，避免重叠。

ℍ² 推荐定义（你的起步方案）

r（半径）

层级深度，由 metric 监督
log loss 低（有效）→ r 小（靠核心）
log loss 高（无效）→ r 大（靠边缘）

θ（角度）

skill 的主语义类别
来自 skill 文本的 embedding 投影
如：0°=优化, 120°=数据, 240°=特征

ℍ³ 推荐定义（加一个正交轴）

r（半径）

层级深度
metric_delta 监督

θ₁（水平角）

skill 领域
优化/数据/特征/模型...

θ₂（垂直角）

skill 类型
Skill/SOP/Condition/FailureMode

这样"领域×类型"两个维度正交分离。如 "优化领域的 SOP" 和 "数据领域的 FailureMode" 在不同位置，不混淆。

ℍ⁵ 推荐定义（4个正交角度轴，skill 库很大时）

轴放什么怎么取值
r（半径）层级深度metric_delta 监督
θ₁（角1）skill 领域优化/数据/特征/模型/集成
θ₂（角2）skill 类型Skill/SOP/Condition/FailureMode/Evidence
θ₃（角3）数据模态表格/图像/文本/时间序列
θ₄（角4）计算成本轻量/中等/昂贵

⚠️ 但别盲目上 ℍ⁵。只有当你的 skill 库真的有 2000+ 个且这些轴都真实存在差异时才用。 否则高维双曲的数值不稳定和计算成本会拖垮你。先用 ℍ² 跑通，验证有效后再升级。

⑤ 一页纸总结

🌳 A部分：为什么只有双曲能装下树

平面(面积∝r，线性)→深层挤；球面(面积有限)→撞墙；双曲(面积∝sinh(r)，指数)→无限装。

📐 B部分：2D vs 3D 怎么选

看 skill 数量：<500 用 ℍ² 足够；500–2000 考虑 ℍ³；>2000 才考虑 ℍ⁵。先用 2D 跑通。

🎯 C部分：坐标轴怎么分配

每个角度轴 = 一个正交语义类别。半径永远 = 层级(metric监督)。ℍ²: r+领域；ℍ³: r+领域+类型；ℍ⁵: r+领域+类型+模态+成本。先从 ℍ² 起步。
