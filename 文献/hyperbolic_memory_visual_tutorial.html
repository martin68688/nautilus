2 什么是双曲空间？用三个生活类比

类比 1：蒲公英 / 椰菜花（最重要）

双曲空间长什么样？就像花椰菜或蕨类植物：

每个分叉点 = 一个 skill。越往外分叉越多 = 具体细节空间指数增长。这就是双曲的"边缘膨胀"。

为什么这对你重要？

你的 skill 库会越来越大（trace2skill 不断蒸馏）。在平面里，几千个 skill 挤在一起，低频的具体 skill 会被高频的通用 skill 淹没（向量检索时排不上）。

但在双曲空间，边缘有无限空间装这些具体的、低频的 skill —— 每个 patch 都有自己的"分叉位置"，不被淹没。

这直接解决你的主贡献1：反 prevalent bias（保护低频有效 skill）。

类比 2：地球仪 vs 平面地图

平面地图（欧氏）画地球会有失真——格陵兰岛看起来比非洲还大（因为球面摊不平）。 层级关系在欧氏空间也会失真：你把一棵树硬压平，父子关系会扭曲。

双曲空间是"专门为树形结构设计的地图投影"——它让层级（父子包含）不失真地展开。 你的 skill 图本质是树（含依赖/细化），所以双曲是它的"天然坐标系"。

类比 3：半径 = 深度，方向 = 类别（核心数学直觉）

双曲空间里每个点有两个坐标，分别对应两件事：

坐标代表什么你的 skill 对应
半径 r（离中心的距离）层级深度通用 → 具体（你的拓扑 level）
方向 θ（角度）语义类别skill 属于哪个领域（优化/数据/特征）
这就是混合检索的根源：在平面里，"语义相似"(向量)和"层级关系"(图遍历)是两套系统要拼接。 在双曲里，方向管语义、半径管层级——两件事在同一个坐标里，所以不用拼接。

3 三个核心公式（最小必要数学）

① Poincaré 球 = 双曲空间的具体实现

ℍⁿ = { x ∈ ℝⁿ : ‖x‖ < 1 } ← 就是单位圆/球内部

所有 skill 点都落在半径1的圆内。中心是原点(最通用)，边界(半径→1)是"无限具体"。

② 双曲距离（检索的核心）

两个 skill u, v 在双曲空间的距离：

d_ℍ(u,v) = arcosh( 1 + 2·‖u−v‖² / [(1−‖u‖²)(1−‖v‖²)] )

看起来复杂，但直觉很简单：分母有 (1−‖u‖²)，当 u 靠近边界(具体)时分母→0，距离爆炸式增长。 → 边缘的具体 skill 之间彼此分得很开（不会挤一起）。中心附近则靠得近（通用 skill 聚在一起）。

③ 指数映射（怎么把你的 skill 放进去）

你的 skill 有一个文本 embedding 向量 ẑ（来自 embedding model）。怎么放进 Poincaré 球？

z = exp₀(ẑ) = tanh(‖ẑ‖) · ẑ/‖ẑ‖

tanh 把任意长度压到 [0,1)，自然落在球内。方向(角度)保留语义，长度(半径)变成层级。

关键问题：半径怎么定？
HyperbolicRAG 的做法：无监督预测一个 depth 值当半径（可能猜错）。
你的独有做法（这是你的 novelty）：用 metric 监督半径！ log loss 低的 skill（有效）→ 放靠近有效核心；log loss 高的（无效）→ 推到边缘。
你有 ground truth（metric），它们没有——这是你比 HyperbolicRAG 硬的地方。

4 你的 6 节点 7 边怎么映射到双曲空间

你综述里的设计：6 类节点（Skill/SOP/Condition/FailureMode/Evidence/AggregationStrategy）+ 7 类边。 每类在双曲空间有天然的几何对应：

6 类节点 → 6 个角向扇区

方向(扇区) = 节点类型，半径 = 通用→具体。同类 skill 聚在同一个扇区，不同类型角度分开。

7 类边 → 7 种几何关系

你的边几何表达
prerequisite半径递增的父子（同方向，向外）

5 混合检索：一个查询，三种模式，同一空间

这是双曲最大的优势。同一个查询，agent 可以调三种检索，底层都是双曲距离，不用拼接：

统一打分公式（写进论文的核心）

Score(v|q) = w₁·exp(−d_角度(q,v)) ← 语义（方向） + w₂·exp(−|r_v − r_q|) ← 层级（半径） + w₃·exp(−d_双曲(q,v)) ← 路径（测地）

三项都在同一个双曲空间算，不像 GoS 要"向量召回→图扩展"两阶段拼接。

6 写入：metric_delta 怎么"摆"好一个 skill

当 trace2skill 蒸馏出一个新 skill，它怎么进入双曲空间？三步：

步骤

Step 1：算 skill 文本 embedding → 得到方向角 θ

8 诚实的话：风险与代价

⚠️ 代价1：双曲距离比欧氏贵

arcosh 计算比余弦复杂，且有数值稳定性问题（靠近边界时溢出）。 对策：用 Lorentz 模型替代 Poincaré（更稳定），或加 ε 截断。

⚠️ 代价2：双曲训练难调

双曲梯度（Riemannian Adam）需要特殊优化器，收敛比欧氏慢。 对策：用成熟库（geoopt / pulq），半径用 metric 监督（你有 ground truth，反而比无监督稳）。

⚠️ 代价3：最大风险——"为什么不直接用 GNN？"

审稿必问：普通 GNN(ℝⁿ) 也能编码图结构，为什么非要双曲？ 必须做的消融：双曲 vs 欧氏 GNN，证明双曲在层级 + 低频召回上更好。 若跑不赢，这个 novelty 不成立。

✅ 但你的 ground truth 是独特优势

所有现有双曲记忆/RAG 的层级都是无监督猜的或LLM 算的。 你有 metric_delta 这个客观信号——这让你的双曲半径有验证、可解释、可消融。 这是别人做不到、你独有的护城河。
