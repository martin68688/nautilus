⑤ 基于真实数据的半径方案修正

真实数据否定了"新=log loss 更低"（相关仅 −0.008），因此原方案 r = 0.7·metric + 0.3·recency 需要修正：

原方案问题：给 recency 0.3 权重会错误地把"新但 log loss 高"的 skill 推向有效核心区（Q3 应在边缘，但 recency 高会拉它向核心）。

修正方案：metric 主导 + recency 仅作 tiebreaker

r = sigmoid( 0.9 · norm(1/metric) + 0.1 · norm(recency) )

修正逻辑：因 log loss 越低越好，用 1/metric（或 −metric）归一化作有效性。权重提到 0.9（有效性远比时序重要），recency 降到 0.1 仅 tiebreak。

数据驱动的结论：演化深度半径方案部分成立（"新=特化"弱成立），但"新=log loss 更低"不成立，因此 recency 必须严格从属于 metric。修正后的 0.9/0.1 加权更贴合真实数据。这反而让方案更稳健、更可辩护——你不是在"猜"权重，是用 124 个无泄露节点校准的。

⑥ 这个验证对研究的启示

启示1（修正半径定义）：论文里不能写"r 融合 metric 和 recency（0.7/0.3）"——真实数据证明不成立。应改为"metric 主导（0.9），recency 仅 tiebreak"，并引用 124 节点验证（step-metric 相关 −0.008）作为依据。注意 log loss 是越低越好，用 1/metric 或 −metric 归一化。
启示2（强化"双曲保护低频"叙事）：Q3 有 34 个"新但 log loss 高"的 skill。在 SkillGraph 里会被 Deprecate 丢弃。但在双曲方案里，它们在边缘保持可达——其中某些可能只是没找到适用条件（Q3→Q2 的潜在转化）。这是 vs SkillGraph 的实证差异化。
启示3（实验设计直接可用）：已有真实四象限数据。主实验可直接用这 124 个节点，对比"双曲嵌入检索" vs "平面向量检索"在 Q3（低频有效边缘 skill）上的召回率。
