## 一、先讲通用概念（这几个被问的概率最高）

### 1. 节点（node）、边（edge）、节点粒度（granularity）、schema

- **节点**：图里的一个记忆单元。不同系统"一个节点装什么"差别极大——可以是一条对话事实、一次任务尝试、一个实体、一条方法规则。
- **边**：连接两个节点、并**编码它们之间关系**的有向或无向连线，通常带一个**标签**说明关系类型（如 `similar_to`、`lives_in`、`fixed_by`）。
- **节点粒度**：节点代表的信息的"大小/抽象层级"。粒度从细到粗：实体（"DeBERTa"）< 事实/事件（"用户是素食者"）< 一次完整尝试的 case（输入+输出+结果）< 方法规则 SOP（"小数据集用部分解冻"）< 完整技能 Skill。**粒度决定了图能回答什么问题**——实体图回答"谁和谁有关系"，case 图回答"以前怎么做的"，SOP 图回答"方法学上该怎么做"。
- **schema**：节点/边的"字段结构定义"，即一个节点由哪些字段组成。比如 Mem0ᵍ 规定每个实体节点必须有 (类型, 嵌入向量, 时间戳) 三个字段——这就是它的节点 schema。

> **可能被问**："你说节点粒度，到底怎么界定？" → 答：用认知科学的知识类型界定——declarative（事实）/ episodic（经历）/ procedural（程序性方法）。现有图记忆节点全是前两类，我的 SOP 是 procedural，抽象层级高一级。

### 2. 同质图（homogeneous）vs 异构图（heterogeneous）

- **同质图**：**只有一种节点类型、（通常）一种边类型**。A-MEM 就是同质——所有节点都是"笔记"，边只有 `similar_to` 一种。
- **异构图**：**有多种节点类型和/或多种边类型**。EXG（case 节点 + task anchor 节点，3 种边）、SAGE / Mem0ᵍ（entity 节点 + 关系边）、Zep（entity + event）都是异构。
- **为什么重要**：异构图能表达更丰富的语义。同质图只能问"哪些笔记相似"；异构图能问"哪个任务下、哪次失败被哪次修复纠正了"——因为它区分了节点角色（task vs case）和边角色（contain vs fixed_by）。
- **本研究**：Skill Graph 是**强异构**——6 类节点 + 多类方法学边，比现有任何一个都更细分，因为方法学知识本身是多粒度的（技能含规则、规则有条件、条件防失败）。

> **可能被问**："异构是不是只是节点多了几种、没本质区别？" → 答：本质区别在于**边能否携带角色语义**。同质图的边只有"相似度"一个标量；异构图的边带类型（`prevents` vs `applies_when`），多跳遍历时能沿特定语义的边走，这是向量检索做不到的。

### 3. "图的强弱取决于边类型的信息量"——这句话怎么解释

边携带的信息量是一个**谱系**，从弱到强：

| 边类型 | 信息量 | 例子 | 能支持的推理 |
|--------|--------|------|------------|
| 语义相似 `similar_to` | **最弱** | A-MEM | "找像的" —— 但相似的东西往往冗余 |
| 因果纠错 `fixed_by` | 中 | EXG | "这个错以前怎么修的" |
| 时序失效 `invalid_at` | 中（仅时间） | Zep | "这条信息何时过期" |
| 训练学到的结构角色 | 强（需训练） | SAGE | "这个节点是 hub 还是 bridge" |
| 方法学关系 `prevents`/`refines` | **最强**（本研究） | Skill Graph | "这两个方法解决同一失败但路径不同→组合用" |

**核心论点**：`similar_to` 最弱，因为语义相似的节点彼此也相似，检索回来是"同一思路的变体"（冗余）；而 `prevents`（A 防止失败模式 F）这种**因果/方法学边**能把语义上不相似、但因果上相关的节点连起来——这才是图相对向量检索的不可替代价值。

### 4. 存储后端（storage backend）

指图实际存在什么软件/数据结构里：

- **向量库（vector store）**：存嵌入向量、按相似度检索（如 FAISS、Milvus）。A-MEM 用它存笔记内容 + 一个链接表记录 note 之间的链。
- **FAISS**：Facebook 开源的向量相似度检索库，`IndexFlatL2` 等索引，做近邻搜索。EXG 用它取语义种子（top-K 相似 case）。
- **Neo4j**：工业级**图数据库**，原生支持节点/边/属性、Cypher 查询语言、多跳遍历。SAGE、Mem0ᵍ 都用它——因为它们要做真正的图遍历。
- **时序 KG（temporal knowledge graph）**：在知识图谱基础上给每条边加时间属性（valid_at/invalid_at），Zep/Graphiti 的后端。
- **NetworkX**：Python 的内存图库，轻量、易用，适合万级节点的研究原型。**本研究用它**——因为 Skill Graph 规模小（百级 SOP），重点在算法不在性能。

> **可能被问**："你用 NetworkX 不嫌慢吗？Mem0ᵍ 都用 Neo4j。" → 答：节点规模差几个量级。Mem0ᵍ 是对话实体图（可上万实体），我是蒸馏出的 SOP 图（百级节点），NetworkX 足够；性能不是本研究的贡献点，换 Neo4j 是纯工程问题。

## 二、逐系统术语详解

### A-MEM ⚠️据原论文（本地无 PDF，引用前再核）

- **Zettelkasten（卡片盒笔记法）**：德语"卡片盒"，一种知识管理方法——每条知识写成一张原子卡片，卡片之间手动建立链接，靠链接网络而非目录组织知识。A-MEM 把它搬到 agent 记忆：每条记忆是一张"note"，note 之间自动建语义链。
- **K / V / T / C（笔记的四个字段）**：每张 note 由 LLM 生成结构化属性——
  - **K = Keywords 关键词**：从内容抽的检索关键词。
  - **V = Value / 内容**：记忆的原始内容本身。
  - **T = Tags 标签**：LLM 打的分类标签。
  - **C = Context 上下文**：LLM 生成的一段上下文描述（这条记忆在讲什么背景）。
  - （另有 timestamp 和 links 字段。）
- **similar_to（语义链接）**：note 之间唯一的边类型，表示两条 note 语义相关，由 LLM 在写入时判断建链。
- **向量库 + 链接表**：内容存向量库（供相似度检索），note 间的链接单独用一张表记录。
- **关键自白（§2.2 原文）**：A-MEM 明确说自己的 agency 在"存储和演化（memory construction & evolution）"，而**检索是纯向量的**（§3.4 三个公式：all-MiniLM 编码 + 余弦相似度 + top-10，无 LLM 参与）。这是区分 A-MEM 和"agent 自主检索"的命门。

> **可能被问**："A-MEM 不是叫 Agentic Memory 吗，凭什么说它检索不是 agentic？" → 答：它的"agentic"指写入端 LLM 自主构造 note 和建链；检索端是固定向量管道。论文自己在 §2.2 划了这条界。

### EXG ✅原文（arXiv:2605.17721，§2.1–§2.2 已核对）

- **trajectory（轨迹）**：✅原文——"an interaction trajectory consisting of alternating reasoning, action, and feedback"。即 agent 解一个任务时"推理→动作→反馈"交替的完整序列，终止于产出解或触发失败条件。
- **case（案例，EXG 的原子单位）**：✅原文——"EXG abstracts each completed attempt within a trajectory into a case, which serves as the atomic unit of experience"。注意：**一条轨迹里的每一次完整尝试**被抽象成一个 case（一条轨迹可能含多次尝试）。
- **case 节点 $c_\tau^{(k)} = (\tau, x_\tau, y_\tau^{(k)}, r_\tau^{(k)}, \sigma_\tau^{(k)})$ 逐分量**：
  - $\tau$：任务 id。
  - $x_\tau$：任务输入。
  - $y_\tau^{(k)}$：第 k 次尝试的输出/解。
  - $r_\tau^{(k)} \in \{0,1\}$：正确性标志。
  - $\sigma_\tau^{(k)}$：✅原文——"execution signal summary, such as error messages, failure types, or corrective feedback"（执行信号摘要：错误消息 / 失败类型 / 纠正反馈）。
- **golden case / warning case**：✅原文——"Successful cases ($r=1$) are treated as golden cases, while unsuccessful ones ($r=0$) are treated as warning cases"。成功的叫 golden（正例），失败的叫 warning（反面教材）。
- **Task Anchor 节点 $a_\tau$**：✅原文——每个任务一个锚点节点，"forms a hierarchical structure between task anchors and case nodes"。作用是把同一任务的所有 case 归到一起，提供任务级检索入口。
- **三种边**：✅原文
  - **contain**（anchor → case）：归属关系，task anchor 包含它的 case，构成层级结构。
  - **similarity / `similar_to`**：无向带权边，"An undirected edge $(c_i - c_j)$ labeled as similar_to encodes semantic similarity"。
  - **correction / `fixed_by`**：有向边，"a directed edge $(c_\tau^{(k)} \to c_\tau^{(k')})$ labeled as fixed_by indicates that..."（同一任务多次尝试中，后一次修复了前一次的错误）。
- **FAISS**：检索时用来取语义种子（top-$K_s$=10 相似 case）。
- **与本研究的差异**：EXG 的 case 是 **episodic（一次尝试的快照）**，含具体输入输出；我的 SOP 是 **procedural（蒸馏出的方法规则）**，抽象层级高一级。EXG 的边 `fixed_by` 已有因果味，但仍是"具体错误→具体修复"；我的 `prevents` 是"方法→失败模式类别"，更泛化。

> **可能被问**："EXG 不是已经有经验图 + 因果边了吗，你和它差在哪？" → 答：节点粒度差一级（case vs SOP）+ 检索方式差一级（它固定 ≤2 跳、零 LLM；我 agent 运行时多跳）。这两点是我对 EXG 的精确 novelty 边界。

### SAGE ✅原文（arXiv:2605.12061）

- **entity 节点（实体节点）**：图的基本节点，代表一个实体（人/地点/事件/概念）。带类型、嵌入向量 $x_e$、时间戳 $t_e$。
- **嵌入 $x_e$**：实体的语义向量表示，用于软寻址时算相似度。
- **时间戳 $t_e$**：实体创建/出现的时间，支持时序推理。
- **关系三元组 $(u, r, v)$**：✅原文——"The action $a_t$ contains entity-relation triples $(u, r, v)$"。$u$=源实体，$v$=目标实体，$r$=关系标签。这是知识图谱的标准表示（主-谓-宾）。
- **typed, directed（有类型、有向）**：边带语义类型（如 lives_in）且有方向（u 指向 v）。
- **alias（别名）**：✅原文提到——同一实体的不同称呼（"tip-of-the-tongue phenomenon... alias alignment"）。图里把别名连到同一实体，检索时即使查询用了别名也能命中。
- **时序约束（temporal constraint）**：✅原文——节点/边"encode entities, episodes, documents, aliases, temporal constraints, and multi-hop dependencies"。即关系的时间有效区间，支持"什么时候成立"的推理。
- **异构 + Neo4j**：多类型节点边的异构图，存在 Neo4j。
- **它的特别之处**：写入是**训练式 writer**（GRPO 策略网络），检索是**训练式 GFM reader**（软寻址公式 $s_e(q)=\lambda_1\text{Exact}+\lambda_2\text{Alias}+\lambda_3\max_m\cos(...)+...$ + 结构门控多跳传播）。

> **可能被问**："SAGE 的图 + 多跳传播是不是已经覆盖你了？" → 答：SAGE 的检索是**训练好的模型一次前向**（推理时固定），不是运行时 agent 决策；它无法根据当前这次失败的具体特征临时改变检索路径。我的是 agent 每跳看 observation 再决定下一步。而且它节点是 entity，不是 SOP。

### Mem0ᵍ ✅原文（arXiv:2504.19413，§ graph memory 已核对）

- **有向标记图 $G = (V, E, L)$**：✅原文——"memories are represented as a directed labeled graph $G=(V,E,L)$"。$V$=实体节点，$E$=关系边，$L$=标签（给节点赋语义类型，如 "Alice - Person"）。
- **entity 节点的三个组件**：✅原文——"Each entity node $v\in V$ contains (1) an entity type classification, (2) an embedding vector $e_v$, (3) metadata including a creation timestamp $t_v$"。即（类型分类 + 嵌入 + 时间戳）。
- **关系三元组 $(v_s, r, v_d)$**：✅原文——"$v_s$ and $v_d$ are source and destination entity nodes, and $r$ is the labeled edge connecting them"。
- **explicit / implicit / temporal relations**：
  - **explicit（显式关系）**：LLM 从文本直接抽的关系（"Alice lives in SF"）。
  - **implicit（隐式关系）**：通过推理得出的、未直接说出的关系。
  - **temporal（时序关系）**：带时间约束的关系。
- **entity extractor + relationship generator**：✅原文——两个 LLM 模块，前者从文本抽实体，后者判断实体对之间是否存在关系并打标签。
- **去重**：实体嵌入相似度 ≥ 阈值 Γ 则与已有节点合并。
- **冲突处理**：update 阶段用 LLM-based conflict 判定 → ADD/UPDATE/DELETE/NOOP。
- **反直觉结论**：✅原文——图版（Mem0ᵍ）只比基础版高约 2%，但延迟约 3 倍、token 翻倍。**"图不总是更划算"**——这是你做图记忆时要主动承认并回应的点。

> **可能被问**："Mem0ᵍ 证明了图收益很小（+2%）还更慢，你为什么还要做图？" → 答：Mem0ᵍ 的图节点是 entity、边是 declarative 关系，图带来的额外信息有限。我的图节点是 SOP、边是方法学关系，价值在"发现语义外的方法学联系"——这是 entity 图给不了的。我会用专项实验（Hidden Link Recall）证明这一点，而不是赌端到端 metric。

### Zep / Graphiti ⚠️据原论文（arXiv:2501.13956，本地无 PDF）

- **entity + event 双类型节点**：既有实体节点，也有事件节点（带时间的"发生了什么"）。
- **valid_at / invalid_at（双时序）**：每条边带两个时间属性——这条关系"何时开始有效""何时失效"。这叫 **bi-temporal（双时间）**建模：既记录事件发生时间，也记录信息被系统获知/失效的时间。
- **时序失效（temporal invalidation）**：当新信息让旧关系过期时，不删除旧边，而是给它打 `invalid_at` 时间戳——保留历史、可回溯。这是**唯一基于客观信号（时间）的冲突处理**，但**只覆盖时间维度**（解决"谁更新"，不解决"两个同时有效但矛盾"）。

> **可能被问**："Zep 不是已经做了客观冲突处理（时序）吗？" → 答：它只处理 dynamic 冲突（时间先后）。static 冲突（两个事实矛盾、无时间先后）和 MLE 的双真冲突（两次执行都真但结果矛盾），时间戳判不了。我的客观信号是 metric + 执行条件，能判 Zep 判不了的。

### 本研究 Skill Graph

- **6 类节点**：
  - **Skill**：一个完整技能集合（如 "small-data-transformer-finetuning"），顶层。
  - **SOP**（Standard Operating Procedure，标准操作流程）：单条可执行的方法规则（如"用 partial unfreezing"）。这是图的主力节点。
  - **Condition**：适用条件/上下文（如"小数据集""GPU 时间有限"）。
  - **FailureMode**：失败模式（如"全参微调天花板""冻结 backbone 性能差"）。
  - **Evidence**：客观证据节点，含 metric_delta（指标变化）+ source trace_id（来自哪条轨迹）。
  - **Implementation**：可复用代码模板/配置片段。
- **核心边**：
  - **applies_when**（SOP → Condition）：该规则在什么条件下适用。
  - **prevents**（SOP → FailureMode，⭐核心）：该规则防止哪个失败模式。多跳的关键——多个 SOP 共享一个 FailureMode 时，能沿这条边发现"解决同一问题的不同方法"。
  - **refines**（SOP → SOP）：条件分支细化（两方法不同条件下各自有效，不是冲突）。
  - **conflicts_with**（SOP ↔ SOP）：同条件下的真冲突。
- **NetworkX**：内存图后端（见上文）。
- **为什么是异构 + procedural**：方法学知识天然多粒度（技能含规则、规则有条件、条件防失败、失败有证据），必须用多类型节点表达；且节点是"怎么做"的程序性知识，填补 procedural 图的空白。

## 三、最可能被连环追问的 5 个问题（速答卡）

1. **"这些图本质都是知识图谱，你的有啥不一样？"**
   → 节点的知识类型不同。它们是 declarative（实体/事实）或 episodic（case）；我是 **procedural（SOP 方法学）**。这决定了边的语义不同——它们的边是"谁和谁有关系"，我的边是"什么方法防什么失败、在什么条件下"。

2. **"同质 vs 异构、节点粒度，这些是不是文字游戏？"**
   → 不是。它们决定**多跳遍历能不能携带语义**。同质图多跳只是"相似的相似"（越走越冗余）；我的异构图多跳能沿 `prevents` 走到"语义远但解决同一失败"的 SOP——这是可量化的（Path Diversity / Hidden Link Recall 专项实验）。

3. **"边的信息量怎么客观衡量，别空口说 similar_to 弱？"**
   → 用检索结果的文本方差衡量：`similar_to` 检索回的节点彼此文本相似度高（方差小、冗余）；`prevents` 多跳检索回的节点文本方差大（覆盖不同方法路径）。这就是 Path Diversity@K 指标。

4. **"Mem0ᵍ 已证明图收益小还更慢，你的图凭什么有用？"**
   → 因为价值来源不同。Mem0ᵍ 的图收益来自"实体间关系推理"（有限）；我的图收益来自"发现语义检索看不见的方法学联系"。我不赌端到端 metric，先用 Hidden Link Recall 证机制。

5. **"为什么不直接把 SearchNode 建成图，要先蒸馏？"**
   → SearchNode 是 episodic 的具体尝试（像 EXG 的 case），直接建图就退化成 EXG。先蒸馏才能得到 procedural 的 SOP（高一抽象层级），这是 novelty 的根基。蒸馏 + 建图是两步，缺一不可。
