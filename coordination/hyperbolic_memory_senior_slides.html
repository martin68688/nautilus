Agentic Hyperbolic SOP Memory

面向 MLEvolve 的可导航双曲程序性记忆：把 skill card 升级成 SOP 地图，让 agent 在代码生成前主动找方法、查条件、看冲突。

阶段性汇报：v0 bootstrap hyperbolic graph + online V1 MemoryNavigator
当前口径：已完成结构构建与 runtime 接入；几何有效性仍需 Flat-Twin 对照实验验证。

问题：经验不是“搜到文本”就够了

条件化

同一 SOP 只在特定数据、模型、错误状态下适用；缺少条件判断会造成负迁移。

冲突与风险

两个历史上有效的方法，在当前条件下可能互相矛盾，需要显式检查。

低频关键经验

普通 top-k 容易偏向高频泛化建议，把窄条件、低频但关键的技巧挤掉。

目标：把搜索轨迹里的 procedural experience 变成可检索、可验证、可冲突检查的 SOP 记忆。

核心表示：不是“存 Skill”，而是“存 SOP 地图”

地图层级

  • Skill：区域/路牌，用于粗路由。
  • SOP：最终可执行的方法点。
  • Reference：代码、证据、实现细节。

导航锚点

  • Condition：这个 SOP 什么时候适用。
  • FailureMode：这个 SOP 防止什么失败。
  • Evidence：这个 SOP 的历史支持信号。

一句话：Skill 是区域，SOP 是点，Condition/FailureMode 是路标，Evidence/Reference 是证据附件。

坐标定义

  • 角度：由 title + principle + condition 的 TF-IDF-SVD 方向得到。
  • 半径：由 p_hat + n_use + level 近似得到。
  • 中心：更通用、更高支持、更高置信。
  • 外圈：低频、窄条件、但保留可达性。

Graph Builder Agent：补边但不乱写图

提 patch

从 SOP card 中抽 Condition、FailureMode、Evidence，并提出 applies_when / prevents / refines / conflicts_with。

程序验证

检查 node id、edge kind、文本 evidence；冲突边必须有 opposition terms 和 condition/failure context。

安全落图

Agent 只建议，validator 决定是否写入。当前实现可复现，未来可换成 LLM builder。

这一步避免了“LLM 看起来合理就改图”的风险。

和 SkillGraph 的差异

维度 SkillGraph 本工作

工程接入 偏 RL co-evolution External memory layer，prompt injection，不改 policy 权重

当前边界：哪些还不能夸大

不是最终蒸馏

当前来自 SkillGraph-C compact cards；还不是 transition-level SOP distillation。

半径仍是 proxy

当前用 p_hat / n_use / level；最终应替换为真实 metric_delta。

几何还未证明

已生成双曲坐标；但还要 Hyperbolic vs Flat-Twin 对照证明几何本身有效。

所以当前最准确的表述是：完成了 v0 双曲 SOP 记忆结构和 V1 agentic runtime，而不是完成了最终论文级系统证明。
